# Phase 12 — Journey I: Security Integrity, Signing & Least Privilege

**Status:** Certified & Verified

## 1. Cryptographic Execution Signing (Ed25519)

1. **Tamper-Proof Plan Dispatch:**
   - Every runbook execution plan generated by the OpsKnight Control Plane is cryptographically signed using the Control Plane's private Ed25519 key.
   - The Agent is configured with the Control Plane's execution public key:
     ```bash
     OPSKNIGHT_EXECUTION_PUBLIC_KEY="MCowBQYDK2VwAyEA4rh6gfeViqX14caPZnYHySvy7kxxXk1Y+HDMsacwNOk="
     ```
   - Before executing any command, the Agent cryptographically verifies the plan signature against `OPSKNIGHT_EXECUTION_PUBLIC_KEY`. Any payload modified in transit or by an unauthorized intermediary is immediately rejected with `SIGNATURE_VERIFICATION_FAILED`.

---

## 2. Hardened Container & Process Isolation

1. **Read-Only Root Filesystem:**
   - The Agent container is run with `--read-only`. An attacker cannot write malicious binaries to `/usr`, `/etc`, or `/bin`.
   - Ephemeral state is strictly restricted to an in-memory tmpfs mount (`--tmpfs /tmp`).
2. **Non-Root Execution:**
   - The Agent process runs under non-root UID `1001` (`opsknight-agent`), dropping unnecessary Linux capabilities (`--cap-drop ALL`).
3. **Automatic Output Redaction:**
   - Step outputs, environment blocks, and error diagnostics are scrubbed by `agent/src/output-safety.ts` to redact API keys, session tokens, and passwords before transmission back to the Control Plane.
