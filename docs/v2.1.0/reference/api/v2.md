# OpsKnight Enterprise Public REST API (v2)

OpsKnight Public REST API v2 (`/api/v2/...`) provides a versioned, secure, high-performance platform for programmatic incident response, on-call orchestration, infrastructure automation, runbook remediation, and identity management.

The v2 platform runs alongside legacy endpoints (`/api/...`, `/api/v1/...`, Events API v2) with zero regressions, sharing core certified domain workflows without duplicate business logic.

---

## 1. Architectural Highlights

- **Standard Envelopes**:
  - Success responses return `{ "data": T, "pagination"?: { ... }, "requestId": "req_...", "timestamp": "..." }`.
  - Error responses strictly adhere to [RFC 9457 Problem Details](https://www.rfc-editor.org/rfc/rfc9457.html) with content type `application/problem+json`.
- **OpenAPI 3.1**:
  - Machine-readable specification dynamically served at `GET /api/v2/openapi.json`.
- **High Performance Without Redis**:
  - Sub-millisecond in-memory LRU TTL cache for token lookups and identity resolutions.
  - Two-tier rate limiter: Memory-shield fast path (<0.05ms) blocks abusive request bursts before reaching PostgreSQL connection pools, followed by distributed transactional coordination in Postgres.
  - Keyset cursor pagination avoiding heavy `OFFSET` table scans.
- **Transactional Idempotency**:
  - Safe mutation retries via the `Idempotency-Key` header.
  - Replayed responses include the `Idempotency-Replayed: true` header.
- **Granular RBAC**:
  - 25+ fine-grained API scopes enforce least-privilege access across all 14 product surfaces.

## 2. Authentication & Credentials

All endpoints accept authentication via HTTP Bearer token or `X-API-Key` header:

```http
Authorization: Bearer ok_sa_live_4a8f9b2c...
```
or
```http
X-API-Key: ok_live_3d7e1a...
```

### Credential Types

1. **User API Keys**: Personal access tokens associated with a human responder or administrator. Inherits the user's role-based access control and assigned teams.
2. **Service Accounts**: Dedicated machine identities created specifically for CI/CD, Terraform, CLI, or ChatOps bots (`department: 'SERVICE_ACCOUNT'`). Service accounts own scoped tokens with custom expiration policies.

### Service Account Token Prefixes
- Production: `ok_sa_live_<base64url>`
- Development/Test: `ok_sa_test_<base64url>`

## 3. Rate Limiting Tiers

Requests are rate limited per API key across three tiers per 60-second sliding window:

| Tier | Window Limit | Typical Operations |
|---|---|---|
| `READ` | 120 req / min | Resource queries, listings, directory lookups, on-call resolutions |
| `WRITE` | 60 req / min | Incident actions, service creation, runbook triggers, status updates |
| `SEARCH_EXPORT` | 30 req / min | Audit log searches, complex metric rollups, CSV/JSON exports |

### Rate Limit Response Headers
- `X-RateLimit-Limit`: Maximum requests permitted in current window.
- `X-RateLimit-Remaining`: Remaining request quota.
- `X-RateLimit-Reset`: Unix timestamp (seconds) when quota resets.
- `Retry-After`: Seconds to wait before retrying (sent on `429 Too Many Requests`).

## 4. Keyset Cursor Pagination

List endpoints support deterministic keyset cursor navigation sorted by `createdAt desc, id desc`:

```http
GET /api/v2/incidents?limit=25&cursor=ZXlKaWRP...
```

### Query Parameters
- `limit` (integer, default: 20, max: 100): Page size.
- `cursor` (string, optional): Base64url opaque cursor returned from the previous page's `pagination.nextCursor`.

### Response Structure
```json
{
  "data": [ ... ],
  "pagination": {
    "limit": 25,
    "nextCursor": "ZXlKaWRP...",
    "hasMore": true,
    "total": 142
  },
  "requestId": "req_1728822000_abc",
  "timestamp": "2026-10-13T12:00:00.000Z"
}
```

## 5. RFC 9457 Error Contract

When a request fails, `/api/v2` returns standard `application/problem+json`:

```json
{
  "type": "https://opsknight.com/errors/api-scope-required",
  "title": "API Scope Required",
  "status": 403,
  "detail": "This operation requires the API scope 'incidents:write'.",
  "instance": "/api/v2/incidents",
  "code": "API_SCOPE_REQUIRED",
  "requestId": "req_1728822000_abc",
  "timestamp": "2026-10-13T12:00:00.000Z",
  "retryable": false,
  "fields": []
}
```

## 6. Supported API v2 Endpoints

### Incidents
- `GET /api/v2/incidents` — List incidents with cursor pagination, service/status/urgency filters.
- `POST /api/v2/incidents` — Create incident with domain escalation triggering and idempotency.
- `GET /api/v2/incidents/{id}` — Incident details, watchers, custom fields, and active responders.
- `PATCH /api/v2/incidents/{id}` — Update incident priority, urgency, title, or description.
- `POST /api/v2/incidents/{id}/acknowledge` — Acknowledge incident via certified domain lifecycle.
- `POST /api/v2/incidents/{id}/resolve` — Resolve incident via certified domain lifecycle.
- `POST /api/v2/incidents/{id}/assign` — Reassign incident to responder or team.
- `GET /api/v2/incidents/{id}/timeline` — Paginated audit events and incident milestones.
- `GET /api/v2/incidents/{id}/notes` — List internal responder notes.
- `POST /api/v2/incidents/{id}/notes` — Post an incident collaboration note.

### Services
- `GET /api/v2/services` — List services with active incident counts and escalation policies.
- `POST /api/v2/services` — Register a new service.
- `GET /api/v2/services/{id}` — Service details, associated teams, and SLAs.
- `PATCH /api/v2/services/{id}` — Update service metadata or operational status.
- `DELETE /api/v2/services/{id}` — Archive or delete service (blocked if open incidents exist).

### Teams & Users
- `GET /api/v2/teams` — List teams and membership rosters.
- `POST /api/v2/teams` — Create a new team.
- `GET /api/v2/teams/{id}` — Team details and member list.
- `PATCH /api/v2/teams/{id}` — Update team properties.
- `DELETE /api/v2/teams/{id}` — Delete team (safeguarded against assigned services).
- `GET /api/v2/users` — Directory lookup (passwords, hashes, and internal tokens sanitized).
- `GET /api/v2/users/{id}` — User profile, contact targets, and role memberships.

### Schedules & On-call
- `GET /api/v2/schedules` — List on-call schedules, rotation layers, and timezones.
- `POST /api/v2/schedules` — Create rotation schedule.
- `GET /api/v2/schedules/{id}` — Schedule details with active layers.
- `PATCH /api/v2/schedules/{id}` — Update schedule parameters.
- `DELETE /api/v2/schedules/{id}` — Remove schedule.
- `GET /api/v2/schedules/{id}/on-call` — Calculate effective on-call engineer at any given timestamp using certified escalation engine target resolution.
- `GET /api/v2/schedules/{id}/overrides` — List schedule overrides.
- `POST /api/v2/schedules/{id}/overrides` — Schedule temporary on-call shift override.

### Escalation Policies
- `GET /api/v2/escalation-policies` — List escalation policies and rules.
- `POST /api/v2/escalation-policies` — Create multi-tier escalation policy with target validation.
- `GET /api/v2/escalation-policies/{id}` — Escalation policy details.
- `PATCH /api/v2/escalation-policies/{id}` — Modify escalation rules and delays.
- `DELETE /api/v2/escalation-policies/{id}` — Delete policy (safeguarded against linked services).

### Integrations & Notifications
- `GET /api/v2/integrations` — Inventory of inbound integration connectors (secrets sanitized).
- `GET /api/v2/integrations/{id}` — Integration status and event receipt metrics.
- `PATCH /api/v2/integrations/{id}` — Enable/disable integration or update mappings.
- `GET /api/v2/notifications` — Notification delivery logs with provider attempt counts.
- `POST /api/v2/notifications/{id}/retry` — Safe requeue of failed notification.

### Status Pages
- `GET /api/v2/status-pages` — List status pages.
- `POST /api/v2/status-pages` — Create customer-facing status page.
- `GET /api/v2/status-pages/{id}` — Status page configuration.
- `PATCH /api/v2/status-pages/{id}` — Update appearance and component visibility.
- `GET /api/v2/status-pages/{id}/announcements` — List active incident announcements.
- `POST /api/v2/status-pages/{id}/announcements` — Publish scheduled maintenance or outage update.

### Runbooks
- `GET /api/v2/runbooks` — List published remediation runbooks.
- `GET /api/v2/runbooks/{id}` — Runbook parameters and execution permissions.
- `POST /api/v2/runbooks/{id}/execute` — 202 Accepted preflight preview and execution initiation.
- `GET /api/v2/runbooks/executions/{id}` — Poll execution steps, logs, and status.

### Service Accounts
- `GET /api/v2/service-accounts` — List machine service accounts.
- `POST /api/v2/service-accounts` — Create automation service account.
- `GET /api/v2/service-accounts/{id}` — Service account details and active tokens.
- `DELETE /api/v2/service-accounts/{id}` — Deactivate service account and revoke all tokens.
- `POST /api/v2/service-accounts/{id}/tokens` — Issue fine-grained scoped token.
- `DELETE /api/v2/service-accounts/{id}/tokens/{tokenId}` — Revoke token.

### Postmortems
- `GET /api/v2/postmortems` — Paginated retrospectives with status and incident filters.
- `POST /api/v2/postmortems` — Create postmortem draft for resolved incident.
- `GET /api/v2/postmortems/{id}` — Retrieve postmortem by ID or incident ID.
- `PATCH /api/v2/postmortems/{id}` — Update root cause, resolution, lessons, or publication status.
- `DELETE /api/v2/postmortems/{id}` — Remove postmortem.

### Audit & Reports
- `GET /api/v2/audit-logs` — Query tamper-evident audit records with actor/entity filtering.
- `GET /api/v2/reports/metrics` — Retrieve MTTR, MTTA, incident volume, and SLA breach rates.

## 7. Granular Scope Reference

| Scope | Access Description |
|---|---|
| `incidents:read` | View incidents, notes, and timelines |
| `incidents:write` | Create, acknowledge, resolve, assign incidents and add notes |
| `services:read` | View services and operational statuses |
| `services:write` | Create, update, and manage services |
| `teams:read` | View teams and rosters |
| `teams:write` | Create, update, and manage teams |
| `users:read` | Safe directory lookup |
| `schedules:read` | View schedules and calculate on-call coverage |
| `schedules:write` | Create and modify schedules and shift overrides |
| `escalation-policies:read` | View escalation policies |
| `escalation-policies:write` | Create and modify escalation policies |
| `integrations:read` | View integration statuses |
| `integrations:write` | Modify integration settings |
| `notifications:read` | View outbound notification logs |
| `notifications:write` | Retry failed notification deliveries |
| `status-pages:read` | View status pages |
| `status-pages:write` | Modify status pages and publish announcements |
| `runbooks:read` | View available runbooks |
| `runbooks:execute` | Initiate automated runbook executions |
| `runbooks:write` | Create and edit runbook definitions |
| `service-accounts:read` | View service accounts and token metadata |
| `service-accounts:write` | Create service accounts and issue/revoke tokens |
| `postmortems:read` | View incident postmortems |
| `postmortems:write` | Create, edit, and publish incident postmortems |
| `audit:read` | Query audit log entries |
| `reports:read` | View operational analytics, MTTA, MTTR, and SLA metrics |
| `admin:manage` | Omnipotent administrative access satisfying any v2 scope |
