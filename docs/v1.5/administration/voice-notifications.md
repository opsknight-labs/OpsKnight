# Twilio voice notifications

OpsKnight can place outbound incident calls through the existing Twilio notification provider. A responder can press `1` during the call to acknowledge the incident; acknowledgement uses the same incident lifecycle and SLA path as the web and mobile applications.

## Requirements

- A Twilio account and voice-capable Twilio phone number.
- Outbound HTTPS access from the critical notification worker to Twilio.
- A publicly reachable HTTPS OpsKnight base URL for Twilio status and DTMF callbacks.
- `NEXT_PUBLIC_APP_URL` or `NEXTAUTH_URL` set to that public URL.
- `VOICE_CALLBACK_SIGNING_SECRET` set to a random value of at least 32 characters. If omitted, OpsKnight uses `NEXTAUTH_SECRET`.

Do not create separate voice credentials. Voice uses the Account SID, Auth Token, and From Number stored on the existing Twilio provider.

## Configure Twilio

1. In Twilio, purchase or select a number with Voice capability.
2. In OpsKnight, open **Settings → System → Notification Providers**.
3. Configure **Twilio (SMS & Voice)** with the Account SID, Auth Token, and From Number.
4. Select **Enable Voice Calling**, save, and use a responder's **Send Test** action under notification preferences.

Twilio callback URLs are generated by OpsKnight. No new container or queue is required for Docker, Compose, Helm, or Kustomize deployments. In split-runtime deployments, voice intents are processed as critical notification traffic.

## Enable a responder

1. Store the responder's phone number in strict E.164 form, such as `+14155551234`.
2. Open **Profile → Notification Preferences**.
3. Enable **Voice Calls**.
4. Add **Voice Call** to the relevant escalation-policy steps.

The final channel is the intersection of the escalation step, the responder's preference, endpoint health, provider availability, and quiet-hours policy. Low-urgency voice calls are suppressed during quiet hours; medium- and high-urgency paging follows the existing urgent-notification behavior.

## Call behavior and security

Calls speak the urgency, service name, and short incident title. Pressing `1` acknowledges an open incident and stops its escalation. Resolved incidents and callbacks from an earlier escalation generation cannot change current state.

Every callback must pass Twilio's `X-Twilio-Signature` validation. DTMF callbacks additionally carry a short-lived OpsKnight HMAC token bound to the notification, responder, incident, escalation generation, nonce, and callback purpose. The returned Call SID must match the notification's provider attempt. Replays are recorded and ignored.

Credentials and callback tokens must never be logged. Phone numbers are masked in notification history. Notification expiry, bounded retries, provider admission, concurrency limits, endpoint health, and the Twilio Voice circuit breaker protect against call storms and uncontrolled cost.

## Troubleshooting

- **Voice cannot be enabled:** confirm the Twilio provider has valid credentials, a From Number, and **Enable Voice Calling** selected.
- **No call arrives:** confirm the destination and From Number are E.164, the Twilio number supports Voice, the destination is permitted by the Twilio account, and notification operations do not show a terminal provider error.
- **The call arrives but press 1 fails:** confirm the configured OpsKnight URL is public HTTPS and that a proxy preserves the original path and query string Twilio signs.
- **Trial account failure:** Twilio trial accounts may only call verified destinations.
- **Old call cannot acknowledge:** this is expected after resolution, reopening, token expiry, or a new escalation generation.

Voice calls can incur carrier and Twilio charges. Configure provider rate and concurrency limits appropriate for the workspace before enabling voice on broad escalation policies.
